# 毎週の流行り調査と台本作りの手順

毎週のルーティン（Claude Code）は、この手順に従って作業します。人が読んでも、何をしているか分かるように書いています。

## 1. 条件を読む

- `trend_config.yml`：ターゲット、期間、話題の大きさの下限、優先テーマ、除外テーマ、作る本数
- `insights/*.csv`（`use_own_insights: true` のとき）：自分の投稿の実績。`insights_template.csv` 以外で数値が入っている行を使う
- `scripts/broll_prompts.csv`：使える映像素材（`clips/<name>.mp4`）の一覧

## 2. 流行りを調べる

**調べてよい情報源**：検索エンジンで見つかる公開ページ（ニュース、若い女性向けメディアのトレンド特集、Googleトレンド、各SNSの公式発表やトレンドまとめ記事）

**やらないこと**：Instagram・TikTok・Xへのログイン、自動での数値取得（スクレイピング）。各サービスの規約で禁止されているため

調べること：
- `period_days` 以内に、`target` の層で話題になっているテーマ・言葉・投稿の型（診断、あるある、ランキングなど）
- 再生数などの数値は、記事に公表値が書かれている場合だけ使い、出典を付ける。`min_reported_views` 未満のものは優先度を下げる。数値がない場合は「数値不明」と書く
- `focus_keywords` に近いものを優先し、`exclude_keywords` に当たるものは使わない

候補を5つ選び、それぞれに出典URLを付ける。

### 2-2. Xの話題・急上昇ワードを調べる

次の順で調べ、**アクセスできない情報源は飛ばして先に進む**（止まらない）。

1. **Web検索（常に使える）**：「Xで話題」「トレンド入り」「バズった」などの言葉に `target`（Z世代女子、大学生など）と今月を組み合わせて検索し、**ニュース記事・トレンドまとめ記事**から話題を拾う。Xそのものには入らない
2. **Googleトレンドの急上昇ワード（アクセスできる場合のみ）**：`https://trends.google.co.jp/trending/rss?geo=JP` を取得する。環境のネットワーク設定で許可されていない場合は飛ばし、`weekly_notes.md` に「Googleトレンド：未取得」と書く
3. **Yahoo!リアルタイム検索・Xの公式API・トレンドまとめサイト**：利用規約の確認と有料プラン・許可設定が済むまで**使わない**（`trend_config.yml` の `sources` で切り替える）

### 2-3. 拾った話題のふるい分け

**使う**
- 季節の行事・イベント（ハロウィン、新学期、テスト期間など）
- ハッシュタグ企画、「〇〇界隈」「〇〇コア」などの言葉
- エンタメ・音楽・推し活の話題で、ターゲットが日常的に話題にしているもの
- ライブ配信・コメント交流・「居場所」に関する話題

**使わない（炎上や信用低下のリスクがある）**
- 事件・事故・災害・訃報
- 個人の炎上・スキャンダル・誹謗中傷
- 政治・宗教・社会的に意見が割れる話題
- 特定の個人名・実在の配信者名・芸能人名を、広告の文脈で使うもの
- `exclude_keywords` に当たるもの

**迷ったら使わない。** 使うか迷った話題は `weekly_notes.md` の末尾に「見送った話題」として理由付きで書き、人が判断できるようにする。

### 2-4. 話題の分類

拾った話題は、次の2つに分けて `weekly_notes.md` に書く。

- **直近の話題**（`period_days` 以内）：今週の台本のフックに使う
- **年間トレンド・調査データ**（半年以上前のものを含む）：台本の根拠・文言の方向性に使う。「直近の話題」としては書かない

直近の話題が見つからなかった週は、無理に作らず「直近の話題：見つからず」と書く。

## 3. 自分の実績を反映する

`insights/` に数値がある場合：
- **完走率（completion_rate）**、**保存数＋シェア数**、**フォロー数（follows）** が高い動画の型とフックの言い回しを優先する
- 再生数が多くてもフォローやリンクのクリックにつながっていない型は、宣伝の回には使わない
- 分析結果を `weekly_notes.md` に3〜5行で書く

## 4. 台本を作る

`scripts/weekly.csv` を、今週の台本で**上書き**する（列は `README.md` の「台本CSVの書き方」を参照）。

- 本数は `weekly_output.reels`。宣伝は `promo_ratio` に従う
- `video_id` は `w01`, `w02`, ... とする
- 1本15秒前後。1シーン目はフック（最初の1秒で誰向けか分かる言葉）
- 映像は `scripts/broll_prompts.csv` にある `clips/<name>.mp4` か、`mock` レイアウトだけを使う。**`broll_prompts.csv` は変更しない**（変えるとVeoの作り直しで料金がかかる）
- テロップに絵文字は使わない
- 宣伝の回では、アプリ名に `trend_config.yml` の `product.name` を使う

## 5. 投稿文を作る

`weekly_notes.md` に、動画ごとに次を書く：
- キャプション（「#PR」を必ず含める）とハッシュタグ5個まで
- おすすめの投稿日時（21〜23時が基本）
- AI映像（Veoのclip）を使った動画には「AIラベル：必要」と書く
- 参考にした流行りと出典URL

## 6. 自己チェック（1つでも当てはまれば直す）

- 「稼げる」「絶対」「完全無料」など、断定や誇大な表現がある
- 「出会い」を連想させる表現、未成年を連想させる表現がある
- 実在しない体験談や、実在の数値（視聴者数、ランキング）のように見える表現がある
- 宣伝の動画とキャプションに「PR」がない
- 他人の投稿の文章や構成を、そのまま写している
- 事件・炎上・政治など、2-3の「使わない」話題に乗っている
- Xの話題を、ログインやスクレイピングで取得した（Web検索の記事と、許可された公開フィードだけを使うこと）

## 7. 提出する

`scripts/weekly.csv` と `weekly_notes.md` だけを変更し、プルリクエストを作る。

- タイトル：`今週のリール台本 YYYY-MM-DD`
- 本文：`weekly_notes.md` の要約と、自己チェックの結果

**このプルリクエストをマージすることが「承認」になります。** マージすると GitHub Actions が動画を作ります。
